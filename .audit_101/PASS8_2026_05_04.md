## 0. Executive Summary

Pass-8 surfaced **~675 raw findings → ~275 unique after dedup** (10 Critical / ~140 High / ~165 Medium / ~110 Low / ~250 Info). **Three architectural themes drove most of the remediation work:**

1. **EIP-170 deployability** — Three contracts overflowed the 24,576 B runtime ceiling and one was 32 B over. Resolved via composite reduction: Solmate→Solady ERC721 swap (saves 621 B on staking), JBAC custody migration to a new `TegridyStakingJbacVault` sister (saves 712 B), `TegridyLending` → +`TegridyLendingAdmin` split, `VoteIncentives` → +`VoteIncentivesAdmin` split, optimizer_runs 10→1, 11 storage constants public→internal.

2. **Cross-contract reentrancy** — The JBAC return callback at the end of every staking-position exit path could re-enter via `transferFrom` / `acceptOffer`. Closed (CCR-01 / CCR-02) by reordering: `_clearPosition` (which `_burn`s the position NFT) now runs **before** the JBAC return, so post-burn `_ownerOf[id] == 0` causes any reentrant call to revert.

3. **Restaker disenfranchisement across governance** — Six governance / fee-eligibility consumers (RevenueDistributor, VoteIncentives, MemeBountyBoard, CommunityGrants, ReferralSplitter, GaugeController) read staking-side voting power only, silently disenfranchising users who restaked their staking NFT into TegridyRestaking. Closed by adding `lib/VotePowerOracle` (no-deploy library) summing both sides; consumers rewired to use it.

## 1. Methodology

### Wave 1 — Per-contract deep audit (30 agents)
One agent per source contract. Mandate: read the full file end-to-end, attack from first principles, ignore prior pass closures. Findings span the full severity spectrum.

### Wave 2 — Vulnerability-class scans (40 agents)
Each agent scoped to one named vulnerability class (reentrancy / approval-allowance / FoT / signature replay / oracle / flash loan / integer over/under / front-run / sandwich / griefing-DoS / DoS-by-revert / unchecked-return / arbitrary-call / delegatecall / storage-collision / proxy / init-pattern / read-only-reentrancy / cross-function-reentrancy / cross-contract-reentrancy / first-mint-bias / division-by-zero / floor-rounding-bias / overflow-on-cast / unbounded-array / quadratic-cost / write-during-snapshot / fee-token-skim / pull-vs-push / event-spoof / blockhash / timestamp-dep / gas-token / 2-step-ownership / EIP-2535-diamond / single-tx-batch / token-permit / merkle / dropped-tx / shadow-state). Cross-cuts wave 1.

### Wave 3 — Cross-contract integration (15 agents)
Each agent scoped to one cross-contract pair / triple. Goal: surface invariants that hold per-contract but break under composition.

### Wave 4 — Economic / MEV / game-theory (10 agents)
Each agent scoped to a specific market or incentive layer (LP fee, swap fee, bribe, premium, drop, lending offer, NFT pool, gauge vote, restaking bonus, royalty).

### Wave 5 — Specialized (5 agents)
Compiler version / via_ir / optimizer_runs / metadata stripping / size budgets — one agent. Toolchain (foundry / forge-std / OZ / Solady / Solmate / Universal Router / V4 PoolManager) — one agent. EIP-170 size and constructor patterns — one agent. Test coverage (decorative-revert detection, mock realism, invariant suites, fuzz seeds) — one agent. Latest 2026 DeFi exploit retrospective web research applied to this codebase — one agent.

### Triage & closure
Raw output (~675 findings) deduped to ~275 unique. Closure plan organized into 6 phases: Phase 0 (deployability), Phase 1 (staking/rewards), Phase 2 (lending), Phase 3 (hook/pool), Phase 4 (governance/gauge), Phase 5 (monitoring/misc), Phase 6 (multisig/owner-trust — DEFERRED). Owner-trust subset removed from in-scope queue per scope decision (we are the owner; multisig migration is its own track).

### Phase 1 — Core staking / rewards correctness

- **CCR-01** (cross-contract reentrancy via JBAC return callback) — all 5 staking exit paths reordered so `_clearPosition` (which `_burn`s) runs **before** the JBAC return callback. Closed at [TegridyStaking.sol:2033-2059](../contracts/src/TegridyStaking.sol#L2033).
- **CCR-02** (parallel ghost-restake on TegridyRestaking) — same defense applies; closed by Phase 1.
- **JBAC custody migration** — moved from TegridyStaking direct hold to `TegridyStakingJbacVault` sister contract: `returnJbac` / `claimStrandedJbac` / `getStrandedJbac` / `onERC721Received`. Closed at [TegridyStakingJbacVault.sol](../contracts/src/TegridyStakingJbacVault.sol).
- **Phase 1.6** — VoteIncentives self-bribe arbitrage + sub-quorum claim. Added `depositedOnPair[user][epoch][pair]` tracking, `MIN_BRIBE_CLAIM_QUORUM = 100e18`, errors `BribePoolBelowQuorum` and `SelfBribeClaimForbidden` in both `claimBribes` and `claimBribesBatch`. Closed at [VoteIncentives.sol](../contracts/src/VoteIncentives.sol).
- **Phase 1.7** — investigated and **confirmed not a real finding**. Each consumer (RevenueDistributor, VoteIncentives, MemeBountyBoard, CommunityGrants) operates an independent reward pool; VP is a per-pool claim, not a fungible spent budget.

### Phase 2 — Lending offer-expiry

- **LD-PHASE3.5** — `TegridyLending.LoanOffer` adds `uint64 expiry`. Constants `MIN_OFFER_VALIDITY = 1 hours` / `MAX_OFFER_VALIDITY = 90 days`. Errors `InvalidOfferExpiry` / `OfferExpired`. Backward-compat 5-arg `createLoanOffer` (auto-defaults to MAX) plus new 6-arg `createLoanOfferWithExpiry`. Acceptance gate at [TegridyLending.sol:848](../contracts/src/TegridyLending.sol#L848). Pattern reference: BendDAO / NFTfi / ParaSpace.

### Phase 3 — Hook / Pool / NFT

- **HOOK-ALLOWLIST** — `TegridyFeeHook` PoolKey allowlist via `mapping(bytes32 => bool) approvedPools` + `approvePool` / `revokePool`. Gate at top of `afterSwap` returns zero-fee for unapproved pools (does NOT revert — non-griefable). Closed at [TegridyFeeHook.sol:333-335](../contracts/src/TegridyFeeHook.sol#L333).
- **TF-INT-02** — `TegridyFeeHook.claimFees` and `convertERC20FeesToETH` now WETH-unwrap to ETH (no ERC20 stranding). Closed at [TegridyFeeHook.sol:512](../contracts/src/TegridyFeeHook.sol#L512).
- **NFT-ROYALTY** — `TegridyNFTPool` ERC-2981 royalty enforcement. `IERC2981` interface, `_settleRoyalty` helper using `safeTransferETHOrWrapNoRevert`, royalty deduction in BUY (from spot revenue) and SELL (from seller payout), `RoyaltyPaid` / `RoyaltyFallbackToWETH` events. Closed at [TegridyNFTPool.sol:957](../contracts/src/TegridyNFTPool.sol#L957).

### Phase 4 — Governance / Gauge

- **GOV-INT-01** — `GaugeController` ↔ pair binding mandatory. `pairToGauge` / `gaugeToPair` / `pendingPairForAdd` mappings, mandatory `pair` arg on `proposeAddGauge`, errors `InvalidPair` / `PairAlreadyMapped`. Closed at [GaugeController.sol:107](../contracts/src/GaugeController.sol#L107).
- **GOV-ECON-01** — `lib/VotePowerOracle` library (no deploy footprint) sums staking-side + restaking-side VP. Wired into 6 consumers (RevenueDistributor, VoteIncentives, MemeBountyBoard, CommunityGrants, ReferralSplitter, GaugeController). Pattern reference: Frax veFXS + Convex `veFXSStrategy`.

### Phase 5 — Monitoring / misc

- **ETH-INGRESS-COUNTERS** — `POLAccumulator` and `SwapFeeRouter` add `uint256 public totalETHReceived` + `ETHReceived(sender, amount)` event in `receive()`. Monotonic, one-way ingress witness for off-chain reconciliation against contract balance. Closed at [POLAccumulator.sol:181](../contracts/src/POLAccumulator.sol#L181) + [SwapFeeRouter.sol:2058](../contracts/src/SwapFeeRouter.sol#L2058).
- **DROP-REVEAL-FORCE-RESOLVE** — investigated and **confirmed not a finding**. `TegridyDropV2` is mint-then-reveal (not commit-reveal raffle); reveal is optional one-shot; cancellation is pre-mint only (DEEP-DROP-05); under-reveal cannot brick the drop.

### Phase 6 — Owner-trust / multisig (DEFERRED)

They belong to a dedicated multisig-policy phase since the protocol is currently operated by a single EOA (per [docs/GOVERNANCE.md](../docs/GOVERNANCE.md) honest-threat-model statement) and migration to a Safe multisig is its own track:
