## 2. The four cross-cutting v3 patterns

### Pattern A — Sibling-miss in pass-2 fixes
The pass-2 commit messages claimed "sibling search applied" — but multiple new fixes are themselves missing siblings.
- **DS3-01** — DS2-02's `KickRewardPoolShortfall` event added to `kick()` but not to `_settleRewardsOnTransfer` (same code shape)
- **DR3-03** — DR2-01's 5-site `totalActivePrincipal` decrement missed a 6th site (`emergencyWithdrawNFT`)
- **LD3-H1 + H2 + H3** — every LD2 fix went to NFTLending only; TegridyLending wasn't touched
- **V3-DROP-V2-02 / V2-03 / V2-04** — Drop missing the equivalent fixes Launchpad got

### Pattern B — Over-correction regressions (introduced by pass-2 itself)
- **V3-AMM-H1** — V2-AMM-M3 added `owner()` to sweepETH allowlist; that's the compromised principal in the original M-32 threat model
- **V3-NFTPOOL-04** — V2-NFTPOOL-05 added `whenNotPaused` to `acceptOwnership` — bricks key-loss recovery
- **V3-NFTPOOL-03** — V2-NFTPOOL-07 buffer math now reverts every withdrawal when pool is underwater
- **DR3-01** — DR2-02's autoMaxLock detection breaks the original `min(cached, current) = 0` semantic
- **V3-GOV-03 / V3-GOV-06** — V2-GOV-04 renormalization formula has 50% leak edges at 1-non-top-voter and 0-non-top-voter

### Pattern C — Math edge cases in fix formulas
- **V3-GOV-03**: `(gw * (BPS - cap)) / othersTotal` over-amplifies when `othersTotal` is small
- **V3-GOV-06**: same formula divides by zero when `othersTotal == 0` (single-gauge case)
- **DR3-M-02**: V2-DR-L-03 fix double-decrements `totalRevenue` on shortfall path
- **DEEP-R3-M01**: `minOut > 0` allows `minOut = 1` which is computationally trivial
- **DEEP-R3-H01**: 200k gas cap insufficient for `MAX_POSITIONS_PER_HOLDER = 50`

### Pattern D — Over-narrow/over-broad gate scoping
- **V3-NFTPOOL-01**: V2-NFTPOOL-01 `_swapCaller` applied to BOTH swap functions but the recommendation was just `swapNFTsForETH`
- **V3-NFTPOOL-02**: pause cooldown updates `lastEmergencyAt` on unpause too (asymmetric in intent, symmetric in code)

## 5. Recommended next moves (priority order)

### Immediate (release-blocking)
1. **The 10 v3 Highs** — all are concrete attack sequences or regression in pass-2 fixes; remediate before any deploy.
2. **Cluster 5 sibling-pattern fix** — the agent recommended a shared `TegridyLendingCore` abstract base. The two contracts have diverged across 4 audit passes; merging the shared logic into a base would close ~5-10 future sibling-miss findings preemptively.
3. **Cluster 8 renormalization formula** — V3-GOV-03 + V3-GOV-06 need a corrected formula. Possibly use Curve's `gauge_relative_weight_write` algorithm (no per-gauge cap, relies on natural distribution) instead of the cap-and-renormalize pattern that's now had 3 variants and still leaks.

### Short-term
- **All 31 Mediums** — most are concrete attack sequences; resolve in next remediation pass.
- **21 Lows + 6 Info** — sweep at the same time.

### Strategic — STOP iterating; commission a paid firm
The "fix → re-audit" cycle has produced a measurable maturity gradient (5 Crit → 1 Crit → 1 Crit → 0 Crit), but the remediation cycle is now COSTING Highs (the pass-2 fixes themselves introduced 6 of the 10 v3 Highs). Continuing to iterate has negative ROI past this point.

**Recommendation:** stop after applying the 10 v3 Highs + the architectural changes (TegridyLendingCore + GaugeController formula rewrite), then engage:
- **OpenZeppelin** — strongest on architecture + cross-contract semantic drift
- **Trail of Bits** — strongest on cryptographic / signature / replay
- **Spearbit** — strongest on math precision + accumulator drift
- **Cyfrin** — fastest turnaround for a final pre-deploy pass

The 5 forge invariants from the pass-1 master report would also catch most of the v2/v3 sibling-miss patterns automatically — would have caught DR2-01's 5th-site miss, DS2-02's _settleRewardsOnTransfer miss, and the LD2-* sibling-misses without a re-audit pass.
