**Three regressions stand out as the most serious code-side issues:**

1. **v2-LIB-style cap miscalibration** (DEEP-R2-H01) — my 50 k gas cap on `_recordReferralFee` silently demotes legit referrers with ≥2 staking positions (each `votingPowerOf` cold-read costs ~8.4 k; pre-work eats most of the cap). 2. **Permanent commit-vote lockup** (DEEP-GOV-V2-01) — my MICROSCOPE C2 fix (monotonic `committedPower`) combined with my new DEEP-GOV-08 `_validatePair` at revealVote means a guardian disabling a pair *after* voters commit causes permanent lockup: voters can't reveal (PairDisabled), can't commit again (EXCEEDS_POWER), and forfeit bond + power + bribe share.
3. **DR-02 sibling-miss x4** (DR2-01) — my `totalActivePrincipal` decrement was applied to ONE site; four sibling sites (`unrestake`, `claimAll`, `refreshPosition`, `decayExpiredRestaker`) overwrite `info.positionAmount = 0` *before* the conditional decrement, so the same phantom-principal DOS persists.

## 2. The four cross-cutting v2 patterns

### Pattern A — Pass-1 sibling-search audit gap *recurred* in pass-1's own fixes
Same shape as the original microscope §4 finding. We applied a fix to one entrypoint and missed the obvious siblings.
- **DR-02** fix: 1 of 5 sites (DR2-01)
- **DEEP-DR-M-04** `claimedAtEpoch`: write-paths covered, but `_pendingETH` view doesn't consult it (DR2-M-01)
- **DEEP-DR-L-04** `bannedReferrers`: blocks `setReferrer` but not `claimReferralRewards` (DR2-M-03)
- **kick()** `_settleUnsettled`: replicated `_settleRewardsOnTransfer`'s pre-existing buggy pattern instead of `_getReward`'s post-fix pattern (DS2-01, DS2-02, DS2-03)

**Process recommendation reiterated:** the sibling-search lint must be a CODEOWNERS-blocking review check, not just an audit recommendation.

### Pattern B — Pass-1 fixes were *over-narrow* (right idea, wrong scope)
Several pass-1 mitigations addressed the symptom but missed the symmetry around it.
- **DEEP-DROP-02** `setMintPrice` phase-gate: blocked `setMintPrice` directly but not the `setMintPhase(CLOSED) → setMintPrice → setMintPhase(PUBLIC)` round-trip (DEEP-DROP-V2-01). Same hole on `configureDutchAuction` (V2-03).
- **DEEP-R-H02** `whenNotPaused` on `withdrawPendingDistribution`: pull-pattern paths shouldn't be paused — gives owner an indefinite-DOS lever (DEEP-R2-M02).
- **DEEP-DROP-05** `cancelSale` blocked after first mint: now the entire `refund() / rescueAfterCancellation() / unclaimedRefundPool` plumbing is dead code wasting 2.9 k gas per mint.
- **DEEP-GOV-03** option-b denominator scaling: still leaks emissions on any non-50% top dominance (test only asserts `<= BPS`, not `== BPS`).

### Pattern C — Pass-1 fix introduced a new attack surface
- **DEEP-GOV-V2-01** monotonic `committedPower` + `_validatePair` at reveal: guardian-disabling-after-commit = permanent lockup
- **DR2-02** `boostedAmountAt` `min(cached, current)` clamp: breaks under autoMaxLock kicked-then-claimed flow
- **DR2-03** LP-farming first-staker windfall (Synthetix economics inversion)
- **DEEP-R2-H01** 50 k gas cap silently demotes multi-position referrers
- **DS2-01 / DS2-02** `kick()` rewardPool / forfeiture handling

### Pattern D — Persistent gaps that *3 audit passes* haven't closed
- **M-AMM1** `disabledPairs` / `blockedTokens` gate on `harvest()` — DEEP-AMM-H2 added the gate to `sync` and `skim` but agent V2 reports `harvest()` itself is still ungated (V2-AMM-M4). Need to verify directly.
- **DEEP-DR-M-08** removed `slippageMin*` floors; the TWAP floor is the only attacker-independent guard now. If TWAP itself is manipulated (the original H15/H16 thread), POL is exposed.
