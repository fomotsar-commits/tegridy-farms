# Slither suppression ledger — Medium+ batch 2026-05-18

## Context

`.github/workflows/slither.yml` runs slither with `fail-on: medium` (per AUDIT R056).
A clean run on commit 2221719 surfaced 991 results across 35 contracts in
`contracts/src/`:

| Severity      | Count |
| ------------- | ----- |
| High          |    24 |
| Medium        |   185 |
| Low           |   388 |
| Informational |   391 |
| Optimization  |     3 |

The 209 Medium+ findings were each classified as a false positive driven by
the structure of the codebase (Uniswap V2 oracle pattern, `nonReentrant`-gated
external calls, sentinel-zero gating, deprecated-slot preservation) and
suppressed inline with:

```solidity
// SLITHER 2026-05-18: <one-line rationale tied to the detector>
// slither-disable-next-line <detector1>[,<detector2>...]
<flagged line>
```

The 779 Low/Informational findings were intentionally left in place — they
do not block CI under `fail-on: medium`, and a future cleanup batch can
walk through them at leisure without holding up shipping.

## Suppression categories — Highs

### `arbitrary-send-eth` (3 findings)

| File | Function | Recipient |
| --- | --- | --- |
| `SwapFeeRouter.sol` | `distributeFeesToStakers` | `revenueDistributor.call{value:...}` and `polAccumulator.call{value:...}` |

| `RevenueDistributor.sol` | `executeClaimRecovery` | User, after 48 h timelock + lifetime cap + per-epoch cap |

All three send ETH to addresses that are *not* arbitrary in any practical sense:
the first two are immutable protocol singletons set at construction; the third
is a user receiving their own admin-attested recovery payout.

### `weak-prng` (4 findings)

All four are the canonical Uniswap V2 oracle pattern:

```solidity
uint32 nowTs = uint32(block.timestamp % 2 ** 32);
```

`block.timestamp` is *not* used as a randomness source anywhere in the codebase.
The truncation exists so cumulative-price math can wrap cleanly past the
year-2106 uint32 rollover.

| File | Locations |
| --- | --- |
| `TegridyTWAP.sol` | `update()`, `canUpdate()`, `_getCumulativePricesOverPeriod()` |
| `SwapFeeRouter.sol` | `_readCurrentCumulative()` (TWAP-min-out enforcement) |

### `reentrancy-balance` (7 findings)

All in fee-on-transfer (FoT) swap paths in `SwapFeeRouter.sol` (3) and
`TegridyRouter.sol` (3), plus one in `TegridyLending.pullEscrowRewards`. The
pattern in every case is:

```solidity
uint256 balBefore = IERC20(token).balanceOf(address(this));
router.swapExactETHForTokensSupportingFeeOnTransferTokens{value:msg.value}(...);
uint256 received = IERC20(token).balanceOf(address(this)) - balBefore;
```

Every entrypoint carries `nonReentrant`; the external is the trusted Router.
Slither flags the *balance read before external call → check after* shape,
which is exactly the FoT shape it's named to detect — but the reentrancy
guard is what makes it safe.

## Suppression categories — Mediums

### `incorrect-equality` (70 findings)

Slither flags strict equality on values where range-based comparison is
typically intended (balances, timestamps). Every Medium+ occurrence in this
codebase is a *sentinel* check — exact equality with a known canonical
value is the intent:

```solidity
if (info.tokenId == 0)    return 0;     // 0 = "not staked"
if (totalRestaked == 0)   { … }         // 0 = "empty pool"
if (received == 0)        revert …();   // 0 = "transfer credited nothing"
if (fee == 0 && effectiveFee > 0) fee = 1;  // 0 = "rounded-down dust"
```

No timestamp-equality patterns survived this pass.

### `uninitialized-local` (36 findings)

All cases are explicit-zero declarations like `uint256 preBonus;` that are
written later under conditional logic. Solidity default-initialises uints to
0, which is exactly the value the conditional branch wants when the predicate
is false. Explicit `= 0` would be cosmetic and would compete for stack slots
under `via-ir`.

### `unused-return` (36 findings)

All cases are tuple destructures of a fixed external-interface shape, e.g.:

```solidity
(, uint256 newBoostedAmount,,,,,,, , ,) = staking.positions(tokenId);
```

We need only the named element; the tuple shape is dictated by the consumed
interface and we have no cheaper read. The same pattern was suppressed inline
for the 4 pre-existing `unused-return` sites in `TegridyRestaking.sol`.

### `reentrancy-no-eth` (30 findings)

Every path reaches the flagged function under a `nonReentrant` modifier.
Cross-function reentrancy via view paths (`pendingBonus`, `pendingBase`,
`earned`) is read-only and cannot enable theft. This is the same rationale
documented in the existing `TegridyRestaking.sol:2183` / `:2252` suppressions
from the M5/M10/M11 batch (commit `9e9c6ed`).

### `divide-before-multiply` (13 findings)

The standard precision-vs-overflow tradeoff. Pattern:

```solidity
shareToken = (lpAmount * fairToweli) / totalSupply;
floorToken = (shareToken * (BPS - TWAP_SAFETY_BPS)) / BPS;
```

Combining into `(lpAmount * fairToweli * (BPS - TWAP_SAFETY_BPS)) / (totalSupply * BPS)`
would risk uint256 overflow on the BPS-scale inputs (BPS = 10_000, totalSupply
can be on the order of 1e24+). The same div-first pattern is canonical in
Uniswap V2's `_update` and POL accumulator math.

## Verification

Run from `contracts/`:

```sh
python -m slither . --filter-paths "lib/|test/|script/" --fail-on medium
```

Expected: exit code 0.

The 779 Low/Informational findings remain visible to slither but do not block
CI. A subsequent cleanup PR can walk them down at leisure.

## Maintenance

- A new Medium+ finding introduced by a PR is a CI blocker. Author must
  either fix the code or add an inline `// slither-disable-next-line` with a
  `// SLITHER YYYY-MM-DD:` justification AND a one-line entry in this ledger
  pointing at the new category.
- This ledger and the per-line comments are the source of truth for an
  external auditor (Spearbit/OZ/ChainSecurity) trying to verify why each
  suppression is safe.
- The 9 pre-existing `slither-disable-next-line` comments (in
  `TegridyRestaking.sol`, `TegridyStaking.sol`, `TimelockAdmin.sol`) predate
  this batch and are documented in their own NatSpec/`SLITHER NOTE` blocks.

# Batch 2026-08-30 — the 56 Medium+ that survived the curated-config fix

## Context

The gate's curated config (`contracts/slither.config.json`) started actually
loading in 2026-08 (see the `slither-config` note in
`.github/workflows/slither.yml`). The first Solidity-touching PR after that
(PR #341, push `11f70704`, run 33326737233) surfaced the true surviving set:
**6 High + 50 Medium across 17 files**, all pre-existing on `mvp-launch`, none
in vendored code, none in a deployed contract.

Every one of them was triaged in `docs/SLITHER_TRIAGE_2026_08_22.md` — a
two-pass, refutation-hardened review whose 12 confirmed defects were **fixed in
commit `3acd395b` (2026-08-25)**. This batch is that document's explicitly
deferred final step: line-scoped disposition of what genuinely survives.
Several flagged lines ARE the 08-25 fix code (the `received == 0` guard, the
harvest quote gate, `isSynced`'s readable split, `_credit`'s guarded zero-skip).

## Disposition (per the 08-22 doc: prefer an initializer/assertion over a comment)

### Fixed outright — no suppression

- **`uninitialized-local` (13)** — explicit zero-initializers (`= 0`,
  `= false`, `= address(0)`). Byte-identical IR (Solidity zero-inits locals;
  Yul emits `let x := 0` either way), kills the finding at the source, and
  writes the sentinel into the code instead of a comment — the exact remedy the
  08-22 refutation prescribed for ids 15/19. Files: `TegridyRestaking` (4),
  `TegridyFeeLocker` (3), `StreamingRevenueDistributor` (2),
  `LaunchRugEscrow` (2), `RestakingMonitorView`, `NftfiBnpl`.
  (Supersedes this ledger's 2026-05-18 "explicit `= 0` would be cosmetic"
  stance — the 05-18 comment-suppressed sites are left as-is.)
- **`TegridyPositionMarket.claimEscrowRewards`** — the absolute post-call write
  became the relative `escrowRewardsOwed[msg.sender] -= paid` (08-22 review,
  id 5's prescribed action): equivalent under the guard, and no longer
  dependent on the modifier set staying exactly as-is. The residual
  `reentrancy-no-eth` on the trusted `_pullUnsettled()` is suppressed with that
  rationale.

### Suppressed inline (each site carries a dated `// SLITHER 2026-08-30:` reason)

# 2026-09-04 — the gate could not see `src/lib/`, and four Medium+ additions

## The scope bug this batch exists to fix

`filter_paths` was `lib/|node_modules/|test/|...` — **unanchored**. `contracts/src/lib/`
contains `lib/`, so all nine files there were silently excluded from every run:

    SafeERC721Call  SequencerCheck  StakingRewardLib  StakingViewLib
    SwapFeeRouterConvertLib  TegridyFactoryLib  UniswapV2OracleLibrary
    VotePowerOracle  WETHFallbackLib

That is the entire EIP-170-split layer — including the body of the SwapFeeRouter TWAP floor
and both of its permissionless external functions. Meanwhile this same config's `_scope`
field explicitly lists `lib/SequencerCheck`, `lib/WETHFallbackLib` and `lib/VotePowerOracle`
as in scope. The gate was reporting clean on files it had never opened.

Anchoring each alternative (`^lib/`, `^test/`, …) fixes it. Measured, one variable changed,
slither 0.11.6 over the same tree:

| config                  | findings | files under `src/lib/` with findings | Medium |
| ----------------------- | -------- | ------------------------------------ | ------ |
| unanchored (as shipped) |      323 | 0                                    |      3 |
| anchored                |      345 | 1 — WETHFallbackLib, 42 element hits |      4 |

## The four Medium+ suppressed here

`LighthouseLadder` ×3 — `incorrect-equality`. **These are why trunk stayed red after #348**:
that PR cleared its batch and this file was not in it, so the gate failed on #348's own merge
commit (`fbef640b`). All three are exact-zero branches on internal counters, not the
timestamp/balance comparison the detector is looking for:
  - `rewardPerToken():221` — `_totalBoosted == 0` is a divide-by-zero guard on the DIVISOR of
    the very next expression. Canonical Synthetix StakingRewards shape.
  - `_payRewards():424` — `owed == 0`, nothing-owed early return.
  - `_payRewards():425` — `payable_ == 0`, nothing-payable early return. Anything unpayable
    STAYS owed, so this defers, it never forfeits.

`TegridyStaking` ×1 — `locked-ether`. **Newly visible**: masked while `src/lib/` was excluded.
The payable functions are Solady's ERC721 `approve` / `transferFrom` / `safeTransferFrom`,
payable upstream purely as a calldata-gas optimisation. The contract declares no `receive()`,
so a plain ETH send reverts, and no staking path attaches value — reaching it means
deliberately attaching ETH to an NFT approve. Suppressed rather than patched **because no
patch is possible**: the contract is live, non-upgradeable, and sits at 24,554 B against the
24,576 B EIP-170 ceiling. Twenty-two bytes is less than any rescue function costs.
